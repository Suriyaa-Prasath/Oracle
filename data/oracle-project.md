# Oracle — Multi-Agent RAG System

A seed document so the index isn't empty on first run. It describes this
project only. Add your resume, bio, and other project writeups alongside it,
then re-ingest.

## Overview

Oracle is a multi-agent retrieval-augmented generation system that answers
questions about my resume, projects, and career history. It runs local-first
on Ollama with Llama 3.1 and deploys publicly on Streamlit with the same model
served by Groq.

## Problem

A static PDF resume answers only the questions its layout anticipated. Anyone
reading it who wants to know "has this person shipped anything with vector
search?" has to scan for keywords and infer. I wanted something a recruiter
could interrogate directly, that answered only from real documents rather than
inventing plausible-sounding experience.

## Architecture

Four agents orchestrated as a LangGraph state machine:

- **Router** — classifies each question into document retrieval, tool use, or
  a direct reply. Runs as a single constrained JSON call and falls back to
  retrieval on any failure, since grounded search is the safe default.
- **Research** — embeds the query and pulls the top-k nearest chunks from
  ChromaDB. Hits below a cosine-similarity threshold are discarded, so "no
  evidence found" is a real signal instead of five irrelevant passages.
- **Tool** — dispatches DuckDuckGo web search, Wikipedia lookup, a sandboxed
  calculator, or a calendar tool that turns a scheduling request into a
  downloadable iCalendar file. Tool failures are recorded as observations rather
  than raised, so a rate-limited search degrades the answer instead of
  crashing the request.
- **Synthesis** — composes the final answer from retrieved evidence and tool
  output, with bracketed citations the UI expands back into source documents.
  If the first retrieval pass came back empty it can loop back once with a
  wider net, bounded by a hard iteration cap.

## Technical decisions

**Chunking is token-based, not character-based**, using tiktoken, so chunk
sizes match what the embedding model actually sees. Chunks are packed from
whole paragraphs rather than cut at a fixed offset, which keeps resume bullets
and code blocks intact. Consecutive chunks share a token overlap so a fact
spanning a boundary stays retrievable from both sides.

**Chunk IDs are a hash of source path and chunk index**, making re-ingestion
idempotent — running the pipeline twice updates existing vectors instead of
duplicating the corpus.

**The provider is abstracted behind one module.** Streamlit Community Cloud
has no GPU and roughly a gigabyte of RAM, so Ollama cannot run there. Groq
serves the same Llama 3.1 weights over an API, which means the deployed demo
runs the identical model as local development and switching between them is a
single environment variable.

**Conversation memory rewrites follow-ups into standalone questions.**
Retrieval is stateless: "what about that one?" embeds to nothing useful. A
small model resolves pronouns against the conversation history before the
query reaches the vector store, and returns the original question unchanged on
failure, since a bad rewrite is worse than no rewrite.

**The calculator validates an AST rather than evaluating a string.** Calling
eval on text generated by a language model is arbitrary code execution. The
first version used SymPy to avoid eval, and a security test proved that unsafe
too — SymPy's expression parser calls eval internally, so a payload executed
and its side effect landed before the result failed to parse. It reported
failure while the command had already run. The replacement walks a Python AST
and permits only numeric literals, arithmetic operators, and whitelisted
mathematical functions.

## Stack

Python 3.11+, LangGraph, ChromaDB, sentence-transformers (all-MiniLM-L6-v2),
Ollama, Groq, Streamlit, tiktoken.

## Outcome

The deployed app exposes the agent's reasoning path — which route the router
chose, which nodes executed, which tools fired, and which chunks were retrieved
with their similarity scores — so the retrieval behaviour is inspectable rather
than a black box.
